1 · The story in one minute

Vikram is raising money (a "Seed round") for his logistics software startup. He has a list of 50 investors (VCs) in a table: their name, firm, what they like to invest in, when he last spoke to them, and whether he is waiting for a reply or hasn't written yet.

His problem: the table tells him who but not who to contact now. A VC who wrote about supply chains last week, invested in a logistics company, or spoke at an event is "warm": an email to them now is far more likely to be read. A VC who has been silent for three months is not worth chasing this week.

VC Pulse does the homework for him. Every Monday and Thursday at 7 AM it checks all 50 investors against live public news, blogs and podcasts from the last 30 days. Gemini Flash (Google's AI) reads every item and works out what it means. Simple rules then give each VC a follow-up score and an action, and the system writes those into 4 columns of his table. His own notes and contact history are never touched: the database itself makes that impossible.

Explain it to a 12-year-old: Imagine you want to sell lemonade to 50 neighbours. Knocking on every door every day is tiring. So a robot checks the neighbourhood news twice a week: "Mrs Rao just posted that she's thirsty!", "Mr Khan has been away for 3 months". The robot puts a sticker next to each name (🔥 knock today, 💤 skip this week) and shows you the news it found, so you can check it yourself. But the robot is never allowed to touch your own notebook, where you wrote "Mrs Rao likes extra sugar". It only writes on the stickers.

4 · How it works, step by step

  1. Trigger. Vercel Cron wakes the system Monday and Thursday at 07:00 IST (01:30 UTC). Vikram can also press "Refresh signals now".
  2. Input. It reads Vikram's table (50 investors) from the Neon database.
  3. Context (live data). For each investor, in parallel: Google News for the person, Google News for the firm plus logistics words (to catch deals), their blog or Substack feed, and Apple Podcasts. Only items from the last 30 days with a link and a date are kept (about 460 items per run).
  4. AI judge (Gemini Flash). 10 investors per AI call. For every item Gemini answers: Is it really this investor (or their firm)? What did they do (invested / wrote / spoke / event)? How close is it to logistics (0-3)? What is the event (so 7 articles about one deal count once)? Plus a one-line summary and an email "hook".
  5. Code checks the AI. (a) The text must name the investor, or for a deal be about logistics. (b) A "3/3 logistics" rating needs a logistics word in the text. (c) Each real-world event counts once.
  6. Score (plain code). points = type × topic fit × who acted × freshness. Best signal + 40% of the 2nd + 20% of the 3rd (max 70) + thesis fit (up to 15) + timing from his status (−30 to +10).
  7. Write 4 columns only. last_signal_date, signal_summary, follow_up_score, recommended_action, using the restricted pulse_engine login. A fingerprint of his columns is saved before and after.
  8. Human gate. Vikram opens the dashboard (already up to date), clicks the evidence, asks Gemini for a draft, edits it and sends it himself.

5 · The six smart decisions (say these in the viva)

1. The database guards the notes. Two logins: pulse_engine may write only the 4 signal columns; pulse_founder (the edit screen) may write only Vikram's columns. Postgres refuses anything else ("permission denied"). The powerful owner login isn't even on the server.
2. Proof, not promises. Every run saves an MD5 fingerprint of all Vikram's columns before and after; they match. The "Attack my own database" button shows the refusals live.
3. AI classifies, code calculates. Gemini judges meaning; plain code does the maths. The same evidence always gives the same score, explained line by line in each VC's drawer.
4. Code checks the AI. The evidence must name the investor; "logistics" needs a logistics word; 7 articles about one deal count once. This removed real false positives we found while testing.
5. Official feeds, not scraping. Public RSS feeds and the Apple Podcasts API: legal, stable, no bans. Gemini's Google Search tool switches on automatically when billing is enabled.
6. Never fails silently. If Gemini 3.5 Flash is busy or out of free quota, it falls back to 3.5 Flash-Lite, then 3.1 Flash-Lite. If all fail for a VC, it keeps last time's verdict instead of wrongly calling them "quiet".

7 · Words you need to know

APIA way for one program to ask another for something over the internet (like ordering through a waiter).
API keyA secret password for an API. Kept in Vercel's hidden settings, never on GitHub.
Environment variableA secret setting stored outside the code (our keys and database logins).
Front end / back endWhat you see in the browser / the hidden code on the server that does the work.
Serverless functionCode that wakes up when called and sleeps otherwise; we don't manage any computer.
Cron jobA task that runs on a schedule ("30 1 * * 1,4" = 01:30 UTC every Monday and Thursday).
RSS feedA simple public list of a site's latest articles, made for apps to read.
LLMLarge language model: an AI trained on lots of text that reads and writes language (Gemini).
Prompt / system instructionThe instructions we give the AI (its job description and rules).
JSON schema / structured outputWe force Gemini to answer in an exact format (fields and allowed values), so code can read it reliably.
TemperatureHow creative the AI is. 0.1 for judging (consistent), 0.6 for email drafts (more natural).
HallucinationWhen AI states something untrue. We prevent it: AI only labels items we fetched, each with a real link.
GroundingMaking the AI answer from real sources (our fetched items, or Google Search when enabled).
Least privilegeGive each part only the permissions it needs. Our engine can write 4 columns, nothing more.
TransactionA group of database changes that all succeed or all fail together.
Hash / fingerprint (MD5)A short code computed from data; if anything changes, the code changes. Used to prove notes were untouched.
Rate limit / quotaHow many requests a service allows. Free Gemini 3.5 Flash: 20 calls per day, so we batch 10 investors per call.
FallbackA plan B: if one AI model is busy, use the next one.
DeterministicSame input → same output, every time (our scoring code).

11 · Viva questions and answers

1. What problem does this solve, in one sentence?

It tells a fundraising founder which of his 50 investors are worth contacting this week, with proof from the last 30 days, and keeps his pipeline table updated automatically without touching his own notes.

2. Where is the AI, and why is AI needed here?

Gemini Flash reads each headline and decides whether it's really this investor, what they did, and whether it's about logistics. Keyword matching can't tell "Peak XV led a round" from "a company Peak XV once backed raised from someone else", or a consumer-TV deal from a freight deal.

3. Why didn't you let the AI decide the score?

Scores must be consistent and explainable. AI judges meaning; code does the arithmetic. Same evidence, same score, and every point is shown in the drawer.

4. How do you stop hallucinations?

The AI never searches or invents in the main path: it only labels items we fetched, each with a real URL and the source's date. Structured JSON output, low temperature, and code checks: the text must name the investor, "logistics" needs a logistics word, one event counts once. Rejected items stay visible.

5. Prove the notes can't be overwritten.

Column-level permissions in Postgres. The engine's login can only UPDATE 4 columns, so trying to write notes gives "permission denied". The Notes guard tab shows it live, and run fingerprints match. Also, the engine updates only those 4 columns by id, never by rewriting whole rows.

6. What is "live external data" here?

Google News RSS (person + firm deals), the investors' own blog RSS feeds, the Apple Podcasts API, all fetched at run time and filtered to the last 30 days.

7. Why not LinkedIn or X?

Scraping them breaks their terms of service and gets accounts banned. Official feeds are legal and stable. In a real product we'd use their official APIs with permission.

8. Why Neon instead of Supabase?

Both are Postgres. The schema and permissions are plain Postgres and run unchanged on Supabase; the Supabase free slots were used by earlier projects. Switching is just two connection strings.

9. How does it run twice a week?

Vercel Cron calls /api/cron at "30 1 * * 1,4" (07:00 IST Mon and Thu) with a secret only Vercel knows. All 50 investors are processed in parallel in about a minute.

10. What happens if Gemini is down or out of quota?

It falls back from 3.5 Flash to 3.5 Flash-Lite to 3.1 Flash-Lite. If all fail for an investor, their previous verdict is kept (not wrongly marked "quiet") and the run log counts the error.

11. What does "quiet" really mean?

"No public activity found in our sources in 30 days", not "not investing". The tool states what it checked.

12. How would you measure success?

Founder time saved per session; % of outreach with a concrete hook; reply rate of signal-timed emails versus generic follow-ups; meetings booked per month.

13. What's the cost?

About ₹0 at this scale: Vercel Hobby, Neon free tier, Gemini Flash free tier (~5 calls per run). Paying for Gemini would add Google Search grounding for event coverage.

14. What are the risks?

Same-name mix-ups, news that mentions a firm only in passing, and missing private activity. Mitigated by name checks, visible evidence, and the human gate: Vikram sends every email himself.

15. What would you build next?

Multi-founder accounts (row-level security), Gmail integration to log replies into contact history with consent, Slack/Telegram alerts (code already supports Telegram), and learning the weights from which emails actually got replies.

16. Why is the score out of 100 and what are the weights?

Invested 40, wrote 34, spoke 30, event 26, in the news 14; × topic fit (1.0 / 0.6 / 0.3) × who acted (person 1.0, firm 0.85) × freshness (100% for 7 days → 40% at 30 days). Best + 40% of 2nd + 20% of 3rd, max 70; + thesis fit up to 15; + timing −30 to +10.

17. Why does timing matter?

If Vikram followed up 3 days ago, emailing again looks pushy, so WAIT (−30), even if there's a great signal; the hook is saved for later. If he's been waiting 2+ weeks and the VC just did something relevant, that's the perfect nudge (+10).

18. How did you test it?

Offline tests of the scoring rules (16 checks), live permission tests (26 checks), end-to-end runs on the real server (cron and Refresh), and manual audits of the AI's verdicts, which is how we found and fixed the false positives.

19. Is anything fake?

The investors and every signal are real and live. Only Vikram, his company and his private notes are illustrative, because he is a case character. The README and the app's footer say so.

20. What did you learn?

AI is powerful at judging meaning but must be boxed in: give it real evidence, a strict format and context, let code check it and do the maths, and let the database enforce the rules that matter most.
